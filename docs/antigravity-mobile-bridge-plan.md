# 猫骑龙娘 · 桌面 Agent 桥接与 Android 操控器施工规划

2026-11-26 · 设计交接。第 1、2 节是已确认的产品行为。其余各节给出协议建议、施工顺序和验收条件，外部接口能力以原型实测为准。

## 1. 用户实际怎样工作

电脑开机且桥接服务运行时，用户在 Android APK 中续接电脑上已有的 Google Antigravity 对话。手机发消息给 Google，Google 用自然语言解释进展、翻译提问、复核交付，并驱动 Codex 工作。电脑执行操作、保存记录，也能展示项目进展。用户在 Antigravity 原对话里即可确认派工。手机离线后电脑继续执行，等待本人决定的工作停在对应节点；电脑关机时执行停止。

一个桌面项目对应一个手机项目。项目下可以有多条持久对话；手机记住上次打开的项目和会话，电脑切换窗口不会改变手机草稿的目的地。项目列表汇总运行状态和待办，打开待办能回到来源会话。手机展示 Google 完整回复；GPT 的计划变更、重要文档、测试结论、交付和待审批事项进入主时间线，子 Agent 活动和原始日志按需展开。

以用户的 ICML 项目为参照：

| 角色 | 职责与上下文 |
|---|---|
| Google 监工 | 对接用户明确指定的一条已有 Codex 对话。汇总、翻译、判断方向、对照证据验收。 |
| `idea` | 长期规划和协调入口，用当前对话配置的模型，适合由用户选用高级模型。拆解任务、管理依赖、续用或创建正式 `work` 对话、整合结果。 |
| `work1`、`work2` 等 | 可在电脑 Codex 中打开并继续的长期对话。可并行分工，后一轮可引用前一轮的框架和交付。各自可临时调用内部子 Agent。 |

首次必须由用户显式选择入口，保存稳定的项目及对话标识。名称变更或重启后仍续接原对话，模型以电脑当前配置为准。并行施工由 idea 指定文件或产物归属，冲突的改动由 idea 协调整合。保留项目中其他专题会话。

## 2. 权限与交接契约

| 情形 | 谁决定 | 应有行为 |
|---|---|---|
| 首次派工 | 用户 | 展示发给 idea 的确切原文。用户在 Antigravity 原对话或手机确认，桥接端发送已确认的版本一次。编辑后重新确认。 |
| 既定范围内的失败、漏项、返工 | Google | 可直接指挥 idea 补做并复验，记录依据、指令、结果。 |
| 技术实现中的一般疑问 | work / idea | 利用设计文档、已有决定和已记录的偏好解决。含义不明时向用户澄清。 |
| Codex 明确向本人提问或请求权限 | 用户 | 保留原文、选项、命令和路径，附 Google 中文翻译，原文可立即查看。Google 不代答。任一端答复后另一端显示实际答复，待办关闭。 |
| 改变目标、核心架构、数据去向、权限或费用 | 用户 | Google 解释决策和影响，取得确认后推进受影响的工作。 |

支持按项目自定义授权范围，明确哪些可自动做、哪些由 Google 复核、哪些必须由本人决定。保留 Codex 自己的沙箱和审批；用户授权才可扩大权限。两模型在规则允许时也可主动请求澄清。显式向本人的问题始终由本人回答。

每个项目同时只接入一个监工，默认使用 Antigravity。显式切换到 DSH 等监工时，撤销旧连接及其派工能力。正在进行的 work 继续跑，结果回原 idea。旧监工尚未确认的派工保留历史，接手方重新展示原文并取得确认。已确认决定、未决问题、正在执行的任务随项目保留。

## 3. 桌面桥接与协作协议建议

复用现有 Electron 主进程、事件展示和 Codex App Server 适配。当前入口在 `src/main/main.mjs`，按计划并发调用 `startAgent`；`src/main/codex-app-server.mjs` 创建线程和回合。新增“接入已有项目/入口”的路径，保留现有独立运行方式。验收以桌面端可继续打开的原会话为准。

桌面桥接核心持有项目、会话绑定、任务、审批、交付物和事件日志。对监工提供本地 MCP 工具，例如读项目快照、读增量事件、提交派工草案、交付证据、请求复核。通过独立适配层续接 Antigravity 原会话；MCP 工具调用本身不能证明消息由真人发出，也不能证明适配器能读取原会话。Android 经已配对的设备通道提交用户操作、订阅状态。DSH 后续复用同一核心；通用模型 API 仅预留适配边界。

**派工与传递证据。** Google 给 idea 的任务包含目标、明确范围、验收条件和版本化文档引用。idea 给 work 补上职责、依赖和产物归属。work 回报任务编号、关键状态变化、验证命令或运行编号、证据引用、阻塞和下一步。电脑保存原始报告、设计文档及修订版本；事件携带摘要和可解析的引用，手机可打开对应版本。保留 Google 完整回复。避免各模型轮流复制整段聊天或日志。

**消息与确认。** 建议事件带 projectId、会话/任务 ID、项目内递增 seq、来源、事件类型、关联请求或产物版本。写请求带唯一 commandId，确认另带 draftId、revision 和原文摘要。电脑持久化唯一约束，核验操作人、版本、待办状态和当前监工身份。确认和待发送记录在同一事务写入。外部发送后若回执丢失，先按关联标识核对真实对话；无法核实时显示“发送结果待核对”，禁止盲重试。给用户区分“电脑已收”和“Codex 已收”。

**重连与接手。** 手机持久化最后已应用的 seq，重连后拉取差量、去重、有缺口则重新同步。发送时断线先查询 commandId；已收到则展示回执，确认未收到则保留草稿，由用户查看最新进展后再发。过期待办不可再次提交。切换监工时生成带 seq 的交接快照，包含授权目标、用户决定、各 work 已验证结果、证据、阻塞和待办；新监工加载后追平增量，再发一条“已做什么、在等什么、下一步是什么”的接手回执。旧监工的判断应与实测结果区分。

## 4. 跨网与锁屏

优先采用成熟的 Tailscale 加密通道，能直连时直连，需要时使用加密中继。允许第三方协调和临时转发，用户无需租用或维护公网服务器。仅配对设备可访问桌面桥接，并支持撤销。配对凭据存放在设备安全存储中。手机端系统 VPN 的安装、授权及网络切换体验须真机验证。

首版 APK 包含锁屏通知。默认提醒两类事项：Codex 明确等用户答复，以及 Google 请求复核大方向。锁屏只显示项目名和待办提示，解锁后拉取当前状态及原文。直连和中继解决网络可达性，Android 后台唤醒需单独验证。先测试系统通知授权、前台服务/后台连接在 Doze 和换网后的送达表现。若可靠送达需要另一家推送服务，应报告所需数据和依赖，取得用户确认。普通进度由时间线承载。

## 5. 施工顺序与验收

| 阶段 | 交付与通过条件 |
|---|---|
| P0 · 原会话桥接原型 | 用测试项目验证手机消息进入电脑已有 Antigravity 对话、Google 完整回复可读、原对话里本人的确认能关联到唯一草案版本；证明模型自报“已确认”不能代替本人。用稳定 ID 续接已有 idea，验证 work 在桌面可打开并续聊。记录实际接口、版本、限制。关键能力受阻时先回报。 |
| P1 · 桌面核心 | 持久化事件、权限、回执和交接快照。回放重复确认、两端同时答复、草案改版、落盘后崩溃、外部发送后丢回执。逐项检查最终状态及外部实际派工次数。 |
| P2 · 并行协作 | idea 派发两条正式 work，并行产出可核对的结果。Google 在范围内自动退回漏项；出现范围变化时请求审批。切换监工期间 work 完成，验证结果被新监工补读、旧监工失去访问权。 |
| P3 · Android APK | 交付可安装 APK、构建命令及桌面配对步骤。在真实手机上验证项目/会话切换、增量同步、重要文档浏览、审批原文与翻译、锁屏提醒。分别记录局域网、移动流量直连和中继路径。 |
| P4 · 端到端 | 用户在 Antigravity 确认草案 → 指定 idea 收到一次 → 两个 work 施工 → 一个 work 提出本人审批 → 手机锁屏收到提醒 → 用户在电脑答复 → 手机解锁后显示同一答复。另测手机离线期间生成文档，以及电脑重启后恢复会话和待办。 |

首个施工任务从 P0 开始。向用户交付原型记录时应分别说明已测通、仅具备文档依据和尚未验证的环节。ICML 项目仅作为协作结构参考，联调使用独立测试项目。
